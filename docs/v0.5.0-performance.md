# v0.5.0 — LLM Inference Performance

## Objective

Measure and optimize local Qwen3-8B inference performance
across quantization, runtime deployment, and concurrent
request execution.

## Experiments

### 1. Quantization

Q4_K_M and Q5_K_M were compared under the same controlled
Docker-based llama.cpp configuration with fixed 256-token
completions.

Q4_K_M achieved 12.20 mean generation tok/s compared with
10.98 tok/s for Q5_K_M.

Result: Q4_K_M provided approximately 11.1% higher mean
generation throughput for the tested configuration.

### 2. Runtime Deployment

Qwen3-8B Q4_K_M was benchmarked using Docker-based llama.cpp
and native llama.cpp on Apple Silicon.

Docker:
- Mean generation throughput: 12.20 tok/s
- Mean latency: 22.44s
- Mean TTFT: 445.85ms

Native:
- Mean generation throughput: 33.28 tok/s
- Mean latency: 7.87s
- Mean TTFT: 173.27ms

Result:
- 2.73x generation throughput
- 64.9% lower mean latency
- 61.1% lower mean TTFT

A 20-request load test evaluated concurrency levels
1, 2, 4, and 8.

Concurrency 1:
- Aggregate throughput: 31.44 tok/s
- P95 latency: 4.19s

Concurrency 4:
- Aggregate throughput: 68.24 tok/s
- P95 latency: 7.75s

Concurrency 8:
- Aggregate throughput: 69.43 tok/s
- P95 latency: 14.90s

Result:

Concurrency 4 increased aggregate serving throughput by
2.17x over concurrency 1. Increasing concurrency to 8
provided only 1.7% additional throughput while increasing
P95 latency by approximately 92.3%.

## Selected Configuration

- Model: Qwen3-8B
- Quantization: Q4_K_M
- Runtime: native llama.cpp
- Hardware acceleration: Apple Silicon / Metal
- Server parallelism: 4 slots
- Context size: 8192

This configuration provided the strongest observed balance
between interactive latency and aggregate serving throughput.
